# サイトの修正（PR を作るところまで）

AGENTS.md のルールに従う。依頼者はプログラマーではないので、やり取りは短い日本語で。

## 1. 依頼を確認する

- どのページの、どの部分を、どう変えたいかがはっきりしなければ、作業前に1回だけまとめて質問する（例:「トップページの『まちに、人に、やさしい解体。』の下の3行を変える、で合っていますか？」）
- 価格・補助金・法律・資格・実績の数字は AI が作らない。依頼者からもらった内容だけを使う
- 施工実績・お知らせ・SEO設定の追加ならコード修正ではない → `works-news` スキルへ

## 2. 準備

```bash
git fetch origin main
git switch -c <作業ブランチ名> origin/main   # 例: update/top-message（クラウド環境で決められたブランチがあればそれを使う）
[ -d node_modules ] || npm ci
```

## 3. 修正する

- 変える場所の探し方: 画面に出ている文言でリポジトリを検索する（`grep -rn "検索したい文言" src index.html public/sitemap.xml`）。ページとファイルの対応は AGENTS.md の5章
- **会社情報（電話・住所・メール・LINE URL）は全箇所を検索して一括で直す**（AGENTS.md の6章）
- ページを追加するとき、すべて行う:
  1. `src/pages/新ページ.jsx` を既存ページ（例: `Guide.jsx`）を参考に作る（`PageHeader` を使うと見た目がそろう）
  2. `src/App.jsx` にルートを追加
  3. `src/components/Header.jsx` の PC 用・スマホ用メニュー（2か所）と `Footer.jsx` にリンク（必要なら）
  4. `src/components/SeoHead.jsx` の `PAGE_DEFAULTS` にタイトルと説明文
  5. `public/sitemap.xml` に URL
- 画像を追加するとき: `public/images/` に半角英数字のファイル名で置き、`/images/ファイル名` で参照。大きければ縮小する（`convert 元.jpg -resize '1600x1600>' -quality 80 public/images/新.jpg`）。依頼者から画像ファイルを受け取れない場合は、管理画面か GitHub の画面からアップロードしてもらう方法を案内する
- 既存の書き方（インラインの style、Tailwind のクラス、色の変数）に合わせる。関係ない箇所は直さない

## 4. 確認する

```bash
npm run build
node scripts/screenshot.cjs <変更したページのパス…>    # 例: / /guide
```

- `.screenshots/` にできた画像（`ページ名-desktop.jpg` / `ページ名-mobile.jpg`）を自分で Read して、変更が反映されているか・崩れ・はみ出し・文字化けがないかを確認する。問題があれば直して撮り直す
- お知らせ・施工実績が空なのは、DB の接続情報が無い環境でダミーでビルドしたため。異常ではない
- ビルドが失敗したら原因を直す。直せなければ、何が起きているかを平易に説明して止まる

## 5. コミットして PR を作る

```bash
git status
git diff          # 秘密情報・個人情報・関係ない変更が混ざっていないか確認
git add <変更したファイル>
git commit -m "トップページのキャッチコピーを変更"
git push -u origin <作業ブランチ名>
```

PR は日本語で作る。本文の例:

```
## 変更内容
- トップページのキャッチコピーを「〇〇」に変更

## 確認したこと
- ビルド成功
- PC・スマホのスクリーンショットで表示を確認

## 公開について
マージすると数分で本番サイトに反映されます。
```

## 6. 依頼者に報告する

- 依頼の時点で「公開までおまかせ」と言われていれば、ここで止まらず `publish` スキルで公開まで進め、公開後にスクリーンショットと URL を添えて報告する
- それ以外は、スクリーンショット（PC とスマホ）を送り、何が変わるかを2〜3行で説明する
- 「この内容で公開してよければ『公開して』と言ってください」と伝える
- PR のリンクも添える。PR の自動チェック（Build check）が赤になったら、原因を直してから報告する
- 公開の依頼が来たら `publish` スキルへ
